# PRD: [작업명]

이 문서는 `docs/plan/issue-xxxx-plan.md` 형태의 작업 계획 문서를 작성할 때 사용하는 PRD형 템플릿입니다.

- AI Agent가 읽고 바로 작업 맥락을 이해할 수 있도록 핵심 정보만 작성합니다.
- 이 템플릿을 기준으로 작업별 PRD 문서를 작성하고, 해당 작업의 이슈 번호를 사용해 `docs/plan/issue-xxxx-plan.md` 형식으로 추가합니다.
- 각 항목은 실제 작업에 필요한 내용 위주로 짧고 명확하게 작성하며, 의사결정과 실행에 필요한 핵심 내용만 남깁니다.

---

## 1. 배경

- 현재 어떤 문제나 필요가 있는지 적습니다.
- 왜 지금 이 작업을 해야 하는지 간략하게 적습니다.

예시:

- `docs/plan` 아래 작업 계획 문서가 AI Agent에게 바로 전달하기에는 구조가 다소 모호합니다.

## 2. 목표

- 이번 작업으로 달성하려는 상태를 적습니다.
- 완료 후 무엇이 가능해져야 하는지 확인 가능한 문장으로 적습니다.

예시:

- AI Agent가 작업 배경, 범위, 요구사항, 실행 순서를 한 번에 파악할 수 있는 PRD형 템플릿을 제공합니다.

## 3. 범위

### 포함

- 이번 작업에서 변경하거나 추가할 내용을 적습니다.

### 제외

- 이번 작업에서 의도적으로 다루지 않을 내용을 적습니다.

예시:

- 포함: `docs/plan/template.md` 구조 개편
- 제외: 기존 계획 문서 일괄 변환

## 4. 요구사항


| ID    | 요구사항           | 완료 기준          |
| ----- | -------------- | -------------- |
| REQ-1 | [필요한 동작/문서/정책] | [확인 가능한 완료 조건] |


## 5. 참고 맥락

모든 항목을 채울 필요는 없으며, 관련있는 항목만 작성합니다.

- 관련 파일:
- 관련 이슈/PR:
- 참고 문서:
- 제약/주의사항:

## 6. 작업 계획

진행 규칙: 1번부터 순서대로 하나씩 진행하며, 각 단계마다 `작업 완료 → 자체 검증 → 필요 시 수정 또는 사용자 확인 → 사용자 검수 → 다음 단계 진행` 순서를 따릅니다.

1. [첫 번째 작업]
2. [두 번째 작업]
3. [세 번째 작업]
4. ...

## 7. 검증

- 요구사항별 완료 기준이 충족되었는지 확인합니다.
- 변경 범위가 `포함` 항목 안에 머물렀는지 확인합니다.
- 필요한 테스트, 문서 확인, 수동 확인 결과를 기록합니다.
